# Дивидендный гэп

Веб-приложение для акций Мосбиржи. Что оно показывает:

- **ближайшие дивиденды**: дату закрытия реестра, примерный последний день покупки, размер выплаты, доходность, статус «объявлен» или «прогноз»;
- **статистику закрытия дивидендного гэпа** по каждой акции и по рынку в целом: долю закрытых гэпов, сколько из них закрылось за 7, 30, 90 и 365 дней, медиану дней до закрытия, средний размер гэпа;
- **карточку акции**: график цены с отметками отсечек и закрытий, а также историю всех гэпов.

## Источники данных

| Что | Откуда |
|---|---|
| Дивиденды: история, объявленные, прогнозы | [dohod.ru](https://www.dohod.ru/ik/analytics/dividend), парсинг HTML |
| Дневные котировки (TQBR) | [MOEX ISS](https://iss.moex.com/iss/reference/), публичный API |

В ISS тоже был список дивидендов (`/securities/{ticker}/dividends`), но теперь этот метод их не отдаёт. Поэтому дивиденды берутся с dohod.ru.

## Методика

- **Последний день с дивидендом (cum-день).** Сделка должна пройти расчёты не позже даты закрытия реестра. Режим расчётов менялся: до 02.09.2013 был T+0 (EQBR), с 02.09.2013 — T+2, с 31.07.2023 — T+1. Поэтому cum-день — это последний торговый день не позже даты реестра, сдвинутый назад на 0, 2 или 1 торговый день соответственно.
- **Гэп** = (закрытие cum-дня − открытие ex-дня) / закрытие cum-дня.
- **Гэп закрыт** в первый день, начиная с ex-дня, когда цена закрытия ≥ закрытия cum-дня. «Дней до закрытия» считаются в календарных днях от ex-дня; 0 означает, что гэп закрылся в тот же день.
- **«Закрыто ≤ N дней»** считается только по отсечкам, после которых уже прошло N дней (или гэп закрылся раньше). Иначе свежие отсечки занижали бы долю.
- **Сплиты.** И свечи ISS, и суммы на dohod.ru уже скорректированы на сплиты. На случай, если сплит произойдёт между обновлениями, есть страховка: `app/splits.py` находит ночные скачки цены в «круглое» число раз и пересчитывает историю. Сплит можно задать и вручную: `MANUAL_SPLITS` в `app/config.py`.
- **Сессии выходного дня** не учитываются: расчёты по ним проходят в будни.
- Если в один день реестра несколько выплат, они суммируются.

## Запуск

```bash
pip install -r requirements.txt

# первичный сбор данных (~5–10 минут), дальше обновления инкрементальные
python -m app.collector
python -m app.collector --tickers SBER,LKOH      # только выбранные бумаги
python -m app.collector --skip-dividends         # только котировки

# веб-приложение: http://127.0.0.1:8000
uvicorn app.main:app --reload
```

Данные хранятся в SQLite: `data/divgap.sqlite`. Путь можно поменять переменной `DIVGAP_DB`. Обновить данные можно кнопкой «Обновить данные» в интерфейсе или по расписанию через cron:

```cron
30 19 * * 1-5  cd /path/to/dividend-gap && python -m app.collector
```

## Статическая версия

Сайт можно выгрузить без сервера, с данными на момент выгрузки, например для GitHub Pages:

```bash
python -m app.export_static                             # -> site/ (страница + data/*.json)
python -m app.export_static --single dividend-gap.html  # один файл, все данные внутри
```

Однофайловую версию можно открыть двойным кликом, без сервера. Интернет нужен только для загрузки библиотеки графиков (Chart.js с cdnjs). Без него таблицы работают, а графика не будет.

## Автообновление (GitHub Actions + Pages)

Workflow `.github/workflows/update.yml` запускается по будням в 19:37 МСК (и вручную: Actions → «Обновление данных» → Run workflow). Он:

1. собирает дивиденды и котировки; база хранится в кэше Actions, поэтому обновление инкрементальное;
2. прогоняет тесты;
3. публикует сайт на GitHub Pages: `https://<владелец>.github.io/dividend-gap/`;
4. прикладывает однофайловую версию `dividend-gap.html` к запуску (Summary → Artifacts), а также кладёт её на сайт: `…/dividend-gap/dividend-gap.html`.

Чтобы публикация заработала, один раз включите Pages: Settings → Pages → Build and deployment → Source: **GitHub Actions**. На бесплатном тарифе GitHub Pages работают только у публичных репозиториев.

## API

| Метод | Описание |
|---|---|
| `GET /api/upcoming?include_forecast=true` | ближайшая отсечка по каждой бумаге и статистика её гэпов |
| `GET /api/stats` | статистика по всем бумагам и по рынку |
| `GET /api/ticker/{SECID}` | карточка: дивиденды, события гэпа, сплиты, цены |
| `POST /api/update` | запустить сбор данных в фоне |
| `GET /api/update/status` | идёт ли сбор, время последнего обновления |

## Структура

```
app/
  config.py     настройки
  db.py         схема SQLite
  http.py       HTTP-клиент с повторами
  dohod.py      парсер дивидендов dohod.ru
  moex.py       котировки MOEX ISS
  splits.py     поиск сплитов и корректировка цен
  gap.py        расчёт гэпа и статистики (чистые функции)
  service.py    аналитика поверх базы
  collector.py  сбор данных (CLI)
  main.py       FastAPI-приложение
static/         фронтенд (HTML + JS + Chart.js)
tests/          pytest
```
